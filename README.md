# my-mail — 멀티 계정 웹메일 뷰어 (웹 콘솔)

POP/IMAP을 지원하지 않는 메일 서비스를 **웹으로 직접 접속(브라우저 자동화)** 해서
읽어오는 도구입니다. 여러 계정을 등록해 한 화면에서 관리할 수 있습니다.

## 시작하기

1. **`setup.bat`** 더블클릭 → 패키지와 브라우저 자동 설치 (최초 1회)
2. **`run.bat`** 더블클릭 → 웹 콘솔이 브라우저에서 열립니다 (`http://127.0.0.1:8765`)

콘솔을 처음 열면 **등록된 모든 계정의 모든 편지함을 한 번 가져옵니다**
(안읽음 개수 집계 + 없는 메일 로컬 보관). 상단에 진행 바가 뜨고 `⏹ 중지` 로 멈출 수 있으며,
서버가 켜져 있는 동안 페이지를 새로고침해도 다시 돌지 않습니다.
언제든 `⭳ 전체 가져오기` 로 다시 실행할 수 있고, `config.json` 의
`"sync_on_start": false` 로 자동 실행을 끌 수 있습니다.

서버는 `127.0.0.1` 에만 바인딩되어 **이 PC 밖에서는 접속할 수 없습니다.**
종료하려면 검은 콘솔 창에서 `Ctrl+C` 를 누르거나 창을 닫으세요.

## 웹 콘솔 사용법

화면은 **계정 → 전체 편지함 → 편지함 → 본문** 4단으로, 왼쪽에서 오른쪽으로 좁혀갑니다.

| 칸 | 내용 |
|---|---|
| 1. 계정 | 등록한 계정 (초록 점 = 세션 저장됨) |
| 2. 전체 편지함 | 그 계정의 **모든 편지함을 한 번에** 나열 (받은편지함·보냄·스팸·직접 만든 폴더 등) |
| 3. 편지함 | 선택한 편지함의 메일 목록 |
| 4. 본문 | 클릭한 메일의 내용 |

- **계정 추가** — 오른쪽 위 `＋ 계정 추가`. 이메일 도메인을 보고 서비스를 자동 추천합니다.
- **메일 보기** — 계정을 클릭하면 편지함 목록이 뜨고 받은편지함이 자동으로 열립니다.
  다른 편지함을 클릭하면 그 편지함의 메일을, 메일을 클릭하면 본문을 보여줍니다.
- **자동 보관** — 편지함을 열면 아직 저장 안 된 메일을 **자동으로** 로컬에 복사합니다.
  상단에 `💾 새 메일 N건 · 본문 N건` 처럼 진행 상황이 표시됩니다.
- **안읽음 개수** — 계정과 편지함 오른쪽에 배지로 표시됩니다. `–` 는 아직 세지 않았다는
  뜻이고, 상단 `🔄 안읽음 세기` 를 누르면 모든 편지함을 돌며 갱신합니다
  (편지함당 몇 초 걸리며, 진행률이 버튼에 표시됩니다).
- 화면이 좁으면 본문 칸이 아래로 내려가고, 더 좁으면 4단이 세로로 쌓입니다.
- **로그인** — 세션이 없거나 만료되면 자동 로그인을 시도하고, 캡차나 2단계 인증이
  필요하면 브라우저 창이 뜹니다. 로그인을 마친 뒤 `로그인 완료됨 · 확인` 을 누르세요.
- **계정 삭제** — 계정 행의 `✕`. 저장된 비밀번호와 세션도 함께 지워집니다.
- 계정·편지함·메일 행 모두 **키보드(Tab / Enter)** 로 조작할 수 있습니다.

### 보관본 우선 표시 (빠름)

한 번 가져온 메일은 **로컬 보관본에서 바로** 보여줍니다. 브라우저를 거치지 않아
목록도 본문도 즉시 열립니다.

- **목록** — 보관본을 먼저 그리고(`archive` 표시), 뒤이어 원본을 확인해 새 메일을 반영합니다.
- **본문** — 보관본이 있으면 즉시 표시하고 `💾 로컬 보관본입니다` 라고 알려줍니다.
  최신 상태가 필요하면 `원본 다시 가져오기` 를 누르세요.
- 보관본이 없는 메일만 실제로 메일 서버에 접속합니다. 이때 받은 본문은
  자동으로 보관되어 다음부터는 즉시 열립니다.

## 터미널에서 쓰기

웹 콘솔이 기본이지만 기존 터미널 방식도 그대로 씁니다.

- **`console.bat`** — 번호를 골라 쓰는 터미널 메뉴
- **`mymail.bat`** — 명령줄 래퍼

```bash
python mymail.py add                     # 계정 추가
python mymail.py list                    # 계정 목록
python mymail.py fetch                   # 전체 계정 최신 메일
python mymail.py fetch --account dev     # 특정 계정
python mymail.py fetch --watch 60        # 60초마다 새 메일 감시
python mymail.py read 1 --account dev    # 1번 메일 본문
python mymail.py folders --account dev   # 폴더 목록
python mymail.py fetch --account dev --folder Notification   # 특정 폴더
python mymail.py read 1 --account dev --folder Notification
python mymail.py login --account dev     # 수동 로그인
python mymail.py inspect --account dev   # 셀렉터 튜닝용 구조 덤프

python mymail.py sync                              # 모든 계정 · 모든 편지함 가져오기
python mymail.py unread --account dev              # 편지함별 안읽음 개수
python mymail.py archive --account dev             # 받은편지함 보관
python mymail.py archive --account dev --all-folders   # 모든 편지함 보관
python mymail.py fetch --account dev --no-archive      # 자동 보관 끄기
```

`fetch` 는 실행할 때마다 **아직 저장 안 된 메일만** 자동으로 보관합니다.

## 보안 / 개인정보

- 비밀번호는 `accounts.json` 에 **평문으로 저장**됩니다. 이 파일을 공유하지 마세요.
- 계정마다 별도 브라우저 프로필(`user_data/<계정ID>/`)을 써서 세션이 섞이지 않습니다.
- 메일 본문은 원격 HTML 을 그대로 넣지 않고 **텍스트로만** 표시합니다
  (외부 이미지 추적·스크립트 삽입 방지).
- 메일을 열면 서버에서 **'읽음' 처리**됩니다.

## 로컬 보관함

메일은 `archive/<계정ID>/<편지함>/<메일키>.json` 으로 저장됩니다.
메일키는 `보낸사람 + 제목 + 날짜` 해시라서, **이미 있는 메일은 다시 복사하지 않습니다.**

```json
{ "key": "...", "account": "dev", "folder": "Notification",
  "sender": "...", "subject": "...", "date": "...",
  "first_seen": "2026-08-24T22:14:46+09:00",
  "body_saved": true, "body": "...", "header": "..." }
```

### 안읽은 메일은 본문을 건너뜁니다

본문을 가져오려면 메일을 **열어야** 하고, 열면 서버에서 **읽음 처리**됩니다.
그래서 기본값은 안읽은 메일의 본문을 건너뜁니다 — 그러지 않으면 보관을 돌릴 때마다
모든 메일이 읽음으로 바뀌어 **안읽음 개수 기능이 무의미해지기 때문**입니다.

안읽은 메일도 보낸사람·제목·날짜는 즉시 저장되고, 나중에 그 메일을 읽으면 본문이
채워집니다. 지금 당장 본문까지 받으려면 `--include-unread` 를 쓰세요
(해당 메일들이 읽음 처리됩니다).

`archive/` 는 개인 메일이 담기므로 `.gitignore` 로 제외되어 있습니다.

## 다른 메일 서비스 추가하기

`config.json` 의 `providers` 에 항목을 추가합니다.

| 키 | 설명 |
|---|---|
| `login_url` | **실제 로그인 폼이 있는 주소** |
| `mail_url` | 받은편지함 주소 |
| `login_redirect_markers` | 로그인 페이지임을 알려주는 URL 조각 |
| `logged_in_markers` | 로그인 성공 판정용 — 메일함 주소 조각 |
| `login_form` | `id` / `pw` / `submit` 셀렉터 (2단계 폼도 지원) |
| `row`,`sender`,`subject`,`date` | 목록 행과 각 필드 셀렉터 |
| `list_container` | 목록 컨테이너 — 빈 폴더와 추출 실패를 구분하는 데 씀 |
| `folders` | 폴더 트리 셀렉터 (`node`/`name`/`current_class`/`url`) |
| `view.subject/header/body` | 본문 화면 셀렉터 |

최상위 옵션으로 `sync_on_start`(시작 시 전체 수집 여부)와
`sync_limit`(편지함당 최대 수집 메일 수, 기본 50)이 있습니다.

`row` 나 `view.body` 를 비워두면 휴리스틱 추출기가 자동으로 추정합니다.
정확도가 떨어지면 `python mymail.py inspect --account <계정ID>` 로 실제 구조를
확인해 셀렉터를 채우세요.

## 문제 해결

**"수동 로그인은 성공인데 메일 확인은 실패"** — 로그인 판정 버그로, 수정되었습니다.
이제 "로그인 페이지가 아님" 이 아니라 **실제 메일함 주소 도달**(`logged_in_markers`)로
판정합니다. 새 서비스를 추가할 때 이 값을 꼭 채우세요. 로그아웃 상태에서 로그인 페이지가
아니라 **마케팅/가입 페이지로 튕기는 서비스**(Zoho)가 있어, 없으면 오판합니다.

`login_url` 도 반드시 실제 로그인 폼이 있는 주소여야 합니다. `https://mail.zoho.com` 은
가입 안내 페이지로 가므로 `https://accounts.zoho.com/signin?...` 을 씁니다.

**"메일을 찾지 못했습니다"** — 새 메일이 없다는 뜻이 **아니라** 목록을 긁어내지 못했다는
뜻입니다. (폴더가 정말 비어 있으면 `이 폴더에 메일이 없습니다` 로 따로 표시됩니다.) 목록 셀렉터가 안 맞거나 SPA 렌더링이 끝나기 전에 읽어서 생깁니다.
`inspect` 로 구조를 확인해 `config.json` 을 맞추세요.

## 참고

- 네이버/다음 프리셋 셀렉터는 서비스 개편 시 바뀔 수 있습니다.
  안 맞으면 자동으로 휴리스틱 모드로 전환됩니다.
- 자동 로그인을 반복하면 캡차나 새 기기 확인을 요구할 수 있습니다.
  한 번 수동으로 처리하면 세션이 유지됩니다.
- headless 차단이 의심되면 `config.json` 의 `"headless": false`.
